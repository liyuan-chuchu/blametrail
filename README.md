# BlameTrail

**The evidence trail behind every line of code.**

BlameTrail is a local-first CLI and GitHub Action for code archaeology. Give it a line of code or a pull request and it follows the trail through Git commits, merged pull requests, linked issues, review notes, and reverts.

```console
$ blametrail explain src/auth/session.ts:42

BlameTrail — evidence for src/auth/session.ts:42-42
Repository: acme/app

Commits
- [regression] [bug-fix] a31c92 Fix session race during token refresh
  Ada · 2026-04-18T09:24:00Z · src/auth/session.ts:42

Pull requests
- [regression] [bug-fix] #812 Prevent duplicate refresh requests

Linked issues
- [bug-fix] #744 Intermittent logout under concurrent requests
```

BlameTrail does not claim that historical decisions are correct. It gives maintainers the original evidence before code is simplified, refactored, or regenerated by an agent.

## Why

`git blame` answers **who** last changed a line. BlameTrail is designed to help answer **why**:

- Was the line introduced by a bug fix, security patch, compatibility constraint, or workaround?
- Which pull request and issue explain the decision?
- Did a reviewer record an important tradeoff?
- Has a similar approach already been reverted?
- Which historical landmines should a maintainer inspect before merging a new PR?

Every remote claim links back to GitHub. The deterministic local analysis works without an AI model or API key.

## Install

BlameTrail requires Node.js 20 or newer and Git.

Install the current GitHub release:

```bash
npm install --global github:liyuan-chuchu/blametrail
```

Or build from source:

```bash
git clone https://github.com/liyuan-chuchu/blametrail.git
cd blametrail
npm ci
npm test
npm link
```

## Use

Explain one line or a range:

```bash
blametrail explain src/auth.ts:42
blametrail explain src/auth.ts:42-60
```

Stay completely offline:

```bash
blametrail explain src/auth.ts:42 --offline
```

Review the historical context around a GitHub pull request:

```bash
blametrail review 128
blametrail review https://github.com/acme/app/pull/128 --markdown
```

Generate machine-readable evidence for another tool or coding agent:

```bash
blametrail explain src/auth.ts:42 --json
```

BlameTrail infers `owner/repository` from the `origin` remote. Override it when necessary:

```bash
blametrail explain src/auth.ts:42 --repo upstream/project
```

For private repositories or higher GitHub API limits, provide a read-only token through the environment:

```bash
export GITHUB_TOKEN=github_pat_...
blametrail review 128
```

Tokens are never accepted as command-line arguments, which helps keep them out of shell history and process listings.

## GitHub Action

BlameTrail can add a read-only historical report to the workflow summary for each pull request. It does not post comments or modify the repository.

```yaml
name: Historical context

on:
  pull_request:

permissions:
  contents: read
  pull-requests: read
  issues: read

jobs:
  blametrail:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: liyuan-chuchu/blametrail@v0.1.0
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
```

The action also exposes the Markdown through its `report` output for maintainers who want to route it elsewhere.

## Evidence model

BlameTrail deliberately separates facts from leads:

1. **Local facts** come from `git blame`, `git show`, and `git log`.
2. **Remote facts** come from GitHub's read-only commit, pull request, review, and issue APIs.
3. **Risk flags** are deterministic keyword-based leads such as `revert`, `security`, `regression`, and `workaround`.
4. **Human judgment** remains the final step. A flag is not a vulnerability or correctness verdict.

See [Architecture](docs/ARCHITECTURE.md) for implementation details.

## Privacy and safety

- Read-only by default; no command edits the repository.
- Local analysis does not upload source code.
- Remote enrichment sends commit SHAs and repository identifiers to GitHub only.
- No telemetry, account, database, or hosted service.
- No model call is required.
- Diff and discussion excerpts are bounded to avoid accidental context floods.

## Current limitations

- Remote enrichment currently supports GitHub.com. Local Git analysis works with any Git host.
- Squash merges and rewritten history can make commit-to-PR association incomplete.
- Issue links are extracted from explicit closing keywords, issue references, and GitHub issue URLs.
- PR review mode analyzes the local checkout's history. Use a full clone rather than a shallow clone.
- Risk flags prioritize explainability over semantic completeness.
