BlameTrail is a local-first CLI and GitHub Action for code archaeology. Point it at a line of code or a pull request and it follows the trail through **commits → pull requests → issues → reviews → reverts**, with links back to the original evidence.

> **In plain English:** when you find a strange line of code, BlameTrail helps answer “who added this, what problem were they solving, and what should I read before changing it?” It gathers the relevant Git commits and GitHub discussions into one report. It does not modify the code or pretend to know the one true reason—it shows the original evidence so a developer or coding agent can make a better decision.

```console
$ blametrail explain src/auth/session.ts:42

BlameTrail — evidence for src/auth/session.ts:42-42
Repository: acme/app

Commits
- [regression] [bug-fix] a31c92 Fix session race during token refresh
  Ada · 2026-04-18T09:24:00Z · src/auth/session.ts:42

Pull requests
- [regression] [bug-fix] #812 Prevent duplicate refresh requests

Linked issues
- [bug-fix] #744 Intermittent logout under concurrent requests
```

> BlameTrail does not claim that an old decision is correct. It gives maintainers the original evidence before code is simplified, refactored, or regenerated by an agent.

## Quick start

Requires Node.js 20+ and Git.

```bash
# Run directly from GitHub
npx github:liyuan-chuchu/blametrail explain src/auth.ts:42

# Or install the command globally
npm install --global github:liyuan-chuchu/blametrail
blametrail explain src/auth.ts:42-60
```

Review a GitHub pull request against the history of every changed file:

```bash
blametrail review 128
blametrail review https://github.com/acme/app/pull/128 --markdown
```

Stay fully offline or produce structured evidence for another tool:

```bash
blametrail explain src/auth.ts:42 --offline
blametrail explain src/auth.ts:42 --json
```

## Why not just `git blame`?

| Question | `git blame` | BlameTrail |
| --- | :---: | :---: |
| Who last touched this line? | ✓ | ✓ |
| Which commit introduced it? | ✓ | ✓ |
| Which PR, issue, and review explain it? | — | ✓ |
| Was it a fix, revert, workaround, or compatibility constraint? | — | ✓ |
| Does this PR revisit a historical landmine? | — | ✓ |
| Can an agent consume the evidence as JSON? | — | ✓ |

## What it does

| Command | Maintainer question | Evidence |
| --- | --- | --- |
| `explain file:line` | “Why does this code exist?” | blame, commits, diffs, PRs, issues, reviews |
| `review 128` | “Has this approach failed before?” | changed files, risky history, related PRs and reverts |
| `--offline` | “Can this stay on my machine?” | local Git only; no network or model call |
| `--json` | “Can my editor or coding agent use this?” | typed, machine-readable evidence report |

Risk labels such as `security`, `regression`, `compatibility`, and `workaround` are transparent keyword-based **leads for human review**, not automated findings.

## GitHub Action

Add a read-only historical report to the workflow summary for each pull request:

```yaml
name: Historical context

on:
  pull_request:

permissions:
  contents: read
  pull-requests: read
  issues: read

jobs:
  blametrail:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - uses: liyuan-chuchu/blametrail@v0.1.0
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
```

The action does **not** post comments, approve pull requests, edit files, or request write permission. Its Markdown report is also available through the `report` output.

## Authentication

Public repositories work without authentication at GitHub's anonymous API limit. For private repositories or higher limits, use a read-only environment variable:

```bash
export GITHUB_TOKEN=github_pat_...
blametrail review 128
```

BlameTrail accepts `GITHUB_TOKEN` or `GH_TOKEN`. Tokens are never accepted as command-line arguments, helping keep them out of shell history and process listings. Override repository detection with `--repo owner/name` when needed.

## Evidence model

1. **Local facts** come from `git blame`, `git show`, and `git log`.
2. **Remote facts** come from GitHub's read-only commit, PR, review, and issue APIs.
3. **Risk leads** are deterministic and inspectable—no hidden scoring model.
4. **Human judgment** remains the final step; every remote claim links to its source.

See [Architecture](docs/ARCHITECTURE.md) for the implementation and trust boundaries.

## Privacy and safety

- Read-only by default; no command modifies the analyzed repository.
- Local analysis never uploads source code.
- Remote enrichment sends repository coordinates and evidence IDs to GitHub only.
- No telemetry, account, database, daemon, hosted service, or model call.
- Diff and discussion excerpts are bounded to avoid accidental context floods.
- Runtime dependency count: **zero**.

## Limitations

- Remote enrichment currently supports GitHub.com; local Git analysis works with any host.
- Squash merges and rewritten history can make commit-to-PR association incomplete.
- PR review mode needs a full local clone; shallow history produces partial evidence.
- Explicit references provide stronger issue evidence than inferred textual similarity.
- Keyword risk leads favor explainability over semantic completeness.

## Build from source

```bash
git clone https://github.com/liyuan-chuchu/blametrail.git
cd blametrail
npm ci
npm test
npm link
```

The CI matrix tests Node 20, 22, and 24 on Windows, macOS, and Linux.

## Contributing

Issues and pull requests are welcome. Good first contributions include public evidence fixtures, GitLab support, richer revert pairing, editor integrations, and documentation improvements. Start with [CONTRIBUTING.md](CONTRIBUTING.md) and preserve the project invariants in [AGENTS.md](AGENTS.md).

If BlameTrail prevents one accidental deletion of a production fix, consider starring the repository—it helps other maintainers find it.
